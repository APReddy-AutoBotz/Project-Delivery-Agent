## Independent bounded reads

HostFiles independently opens a fresh anchored no-follow/nonblocking descriptor.
The root starts at /, walks at most128 components, and matches the actual created
fixture and each pinned scope directory. Files must match the source-approved
size/full hash and actual original device/inode, owner, single-link kind and
expected mode. Every native read is <=65536 bytes and prospectively charged;
only the authenticated remaining size is read, then one EOF byte. Full hash,
final fstat, anchored path and parent directory observations must agree. Actual
returned read counts settle before the post-call guard. Unknown results retain
their full prospective charge. No until-EOF loop or pathname-only hash remains
on an overridden artifact/dependency path.

Only exact .d/.map names <=1MiB may return private bytes after complete hash,
identity, EOF, closure and final clock checks. A bounded bytearray avoids a
separate list object for every short-read byte. Other reads return digest only.
These bytes go directly to the unchanged dependency/map predicates; they are
never placed in public receipts, errors, stdout or encoded transport.

Tool dependency authority comes from the actual completed ToolView's included
rows, destination inodes and directory identities, reconciled with the unchanged
license gate. Artifact authority comes from the strict complete18-row snapshot
and worker inode witnesses. Arbitrary row dictionaries cannot select another
scope, pathname or mode. The owner privately copies those fixed tables.

## Clocks and settlement

The per-copy absolute end is stored once BEFORE worker entry and remains the
same through the inherited copy-hash hook, independent descriptor verification,
closure, receipt and storage settlement. No new3s origin. Storage is unsettled
until that hook completes; every failure restores the full expected reservation.
Later mode/dependency/map/model operations use the original600-second attempt's
normal guard with20-second reserve. All actual boundaries have fresh before/after
guards. Known resource cleanup uses the original cleanup guard, and a late close
cannot publish a successful copy or mode witness. No repaired clock or grace.

This follows the existing accepted guarded ToolView root-I/O pattern. Native
calls are not individually supervised subprocesses. Guards detect crossing
around those calls; they do not promise interruption of a stalled kernel call.

## Finite owner inventory

Four incremental owner slots include ordinary descriptors, pending/uncertain
acquisitions/closures and one opaque census-native slot. This is NOT a process-
wide or measured native-FD claim, and is separate from the worker's16FD budget.
There are at most128 directory components per operation; native acquisitions are
prospectively bounded by256 per allowed operation, conservatively counted in
the owner lifetime bound. Operations are bounded by64 plus six1MiB dependency
files divided by a conservative seven-byte minimum /tool/ token. Root file reads
have an additional aggregate2GiB capacity; storage remains256MiB, with unchanged
32MiB artifact/1MiB text and256MiB source-view per-file bounds. No time, process,
container, storage, operational or accepted-story limit is increased.

Known resources enter ownership before post-call inspection. A possible-effect
acquisition/close fault retains its reservation. Ambiguous descriptors are not
closed again, including after numeric reuse. A failure poisons further ordinary
file access. Public errors use a finite reason vocabulary; arbitrary boundary
exception text is normalized without exposing private bytes.

## Census and actual modes

One bounded os.scandir(fd) invocation reserves its hidden duplicate FD BEFORE
entry. Each next call is guarded, and only18 expected names plus one extra-entry
observation are permitted. No eager list, unbounded sorting or implicit DirEntry
metadata lookup. Exact names and stable descriptor/path directory metadata must
agree. The once-ever census latch forbids retry even after an ambiguous failure.

CPython3.12.3 ignores closedir's native return. The owner records Python API
completion separately and conservatively keeps one opaque native capacity slot
charged until process termination, even after Python close returns. It never
claims that this observes kernel directory-FD closure. Observable API failures
remain sticky, and actual iterator objects remain retained on uncertain close.
Model-only source acceptance is not native-resource qualification. The complete
future packet must retain these explicit qualifiers; stronger actual native
closure predicates cannot be satisfied by this API-only census.

After all18 transfers and exact builder retirement, a fresh normal guard precedes
any census/read/chmod. Files change from0600 to0444, or0555 for models, using the
same independently authenticated descriptor. The full new identity is measured
after the actual fchmod and anchored path check, then published only after known
closure and final guard. Previous mode/ctime witnesses are not reused as though
chmod were invisible.

The artifact directory changes0700->0555 LAST, after all18 actual file-mode
witnesses. This is necessary for model UID1000 to traverse the read-only bind
when the runner UID differs. The host fixture ancestor stays0700; no UID,
privilege, mount or container policy changes. Its same-inode post-mode witness
is likewise measured, not synthesized. Later accesses require the new mode.

## Inherited seams and terminal behavior

The default driver adds only thin methods delegating to historical sha,
read_bytes, iterdir and chmod, plus no-op continuation/mode/ELF hooks. Existing
copy-size/hash, dependency/license, map-input, ELF-schema and model-hash

dependency/map reads, tool dependency hashes, mode/census and normal continuation.

Original owned-container cleanup still runs after any file failure. Known file
resources are closed under the original cleanup clock. Any unresolved object or
descriptor stays strongly held by the attempt through final low-level failure
exit; no ordinary Python finalizer release or retry is permitted. The opaque
census capacity reservation remains separately reported and never becomes a
kernel-known closure claim. Terminal modeled success requires no observable API
uncertainty, no poisoned file owner, complete modes/producer/transfer/model/
receipt and actual container cleanup gates. No native admission follows.
