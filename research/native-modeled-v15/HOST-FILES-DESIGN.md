## Independent bounded reads

HostFiles independently opens a fresh anchored no-follow/nonblocking descriptor.
The root starts at /, walks at most128 components, and matches the actual created
fixture and each pinned scope directory. Files must match the source-approved
size/full hash and actual original device/inode, owner, single-link kind and
expected mode. Every native read is <=65536 bytes and prospectively charged;
only the authenticated remaining size is read, then one EOF byte. Full hash,
final fstat, anchored path and parent directory observations must agree. Actual
returned read counts settle before the post-call guard. Unknown results retain
their full prospective charge. No until-EOF loop or pathname-only hash remains
on an overridden artifact/dependency path.

Only exact .d/.map names <=1MiB may return private bytes after complete hash,
identity, EOF, closure and final clock checks. A bounded bytearray avoids a
separate list object for every short-read byte. Other reads return digest only.
These bytes go directly to the unchanged dependency/map predicates; they are
never placed in public receipts, errors, stdout or encoded transport.

Tool dependency authority comes from the actual completed ToolView's included
rows, destination inodes and directory identities, reconciled with the unchanged
license gate. Artifact authority comes from the strict complete18-row snapshot
and worker inode witnesses. Arbitrary row dictionaries cannot select another
scope, pathname or mode. The owner privately copies those fixed tables.

## Clocks and settlement

The per-copy absolute end is stored once BEFORE worker entry and remains the
same through the inherited copy-hash hook, independent descriptor verification,
closure, receipt and storage settlement. No new3s origin. Storage is unsettled
until that hook completes; every failure restores the full expected reservation.
Later mode/dependency/map/model operations use the original600-second attempt's
normal guard with20-second reserve. All actual boundaries have fresh before/after
guards. Known resource cleanup uses the original cleanup guard, and a late close
cannot publish a successful copy or mode witness. No repaired clock or grace.

This follows the existing accepted guarded ToolView root-I/O pattern. Native
calls are not individually supervised subprocesses. Guards detect crossing
around those calls; they do not promise interruption of a stalled kernel call.

There are at most128 directory components per operation; native acquisitions are
prospectively bounded by256 per allowed operation, conservatively counted in

Known resources enter ownership before post-call inspection. A possible-effect

closed again, including after numeric reuse. A failure poisons further ordinary
