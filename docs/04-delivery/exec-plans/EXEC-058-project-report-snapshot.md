# EXEC-058: Save a selected-project report snapshot

Status: In progress

Requirements: FR-RPT-004, FR-RPT-005, FR-RPT-007, FR-RPT-009, FR-RPT-010 and NFR-SEC-001.

GitHub issue [#13](https://github.com/APReddy-AutoBotz/Project-Delivery-Agent/issues/13).

An authorized project leader can save a management draft and reopen its exact
fact set. Reuse the draft projection, PowerPoint renderer and the append-only
snapshot pattern already used for Atlas. Retain the project, author, stable
snapshot ID and structured facts. Save only when the current facts match those in
the displayed draft. A save retry during the same month reuses the
latest matching fact set. The snapshot ID and original generation time appear
in each channel.

Use the requesting leader's most recent readable delivered report for a
selected-project comparison. Freeze its canonical schedule dates and freshness state, and
the current open canonical decisions with the new report. Recheck both reports'
evidence for each viewer before opening or sharing the digest. Render that context
in the project view, leadership email preview and editable PowerPoint. Show
when a comparison is unavailable, and link the preview to the authenticated
project. Older saved snapshots retain their original content.

Access to a saved draft requires the current project leadership grant and the
same author. Recheck the exact saved freshness assessment and its sources on
every read. If the historical proof is unavailable, withhold the snapshot.
Approval and distribution require a subsequent increment. Keep source text,
recipient details and deck bytes out of snapshot storage.

Extend the existing browser journey to save, reopen and export the same draft
after a newer update policy takes effect. Compare the report ID and exact dates
across outputs and verify denial from a different project. Reverting the route
and panel disables new saves. Existing snapshots remain in the audit history.
