## User outcome and scope

Show a read-only, single-project “Delivery suggestions” panel beside the existing health assessment. Derive rule-based PM or leadership wording from a fresh current schedule snapshot and the merged delivery-advice core. Label the output SCHEDULE_ONLY, source authority not assessed, as-of DB time and review required. This view-level limitation is not a new provenance, freshness or conflict state and does not overwrite ADR-009 classifications. Display trigger, rule, urgency, action, outcome, and authorized source facts, without implying that these observations establish source authority or that actions were approved or executed. This is not a full queue: show that approval items are unavailable because the workflow is not available; do not display zero pending approvals or imply no other health signals. Blocker, freshness, completeness, interpretation and connector write work remain out of scope. Do not claim AC-ADV-002, STORY-025/026 or Issue #11 completion.

## Snapshot and authorization

A fixed GET route for one project authenticates using IdentityService. The route takes one explicit project ID; the server authorizes that exact project without substitution and derives customer, subject, audience and scope. It accepts no caller-supplied subject, project list, authorization flags, evidence or timestamps. For a PM audience require a matching current scoped project_manager grant, authenticated role and the exact PROJECT_MANAGER ProjectResponsibility for that subject. For leadership require a current scoped leadership grant and token role. For dual roles, select the PM audience only when exact responsibility, token role and scoped PM grant all match; otherwise select leadership only if token role and scoped leadership grant independently match; return 404 for inaccessible project or no supported audience. Treat configured multiple PMs as membership, not a requirement to choose a unique routing recipient.

Within one ReadCommitted transaction with the existing 10-second timeout, reuse/refactor the existing health create read path: lock project and relevant current grants/assignment; take the shared advisory lock with exact key schedule-health-policy:<customer>:<project> and the same policy read as writers; require sealed canonical graph when present; read complete bounded milestone/work-item cohorts with existing limit-51 rejection; read current reported status and graph revision, and obtain database time after the required snapshot locks. Preserve Project → grants/assignment → shared schedule-policy advisory lock → CanonicalProject → ordered milestones → ordered work items. Canonical birth locks Project; child inserts lock the canonical parent and sealed schedule children are immutable. The advisory lock is an application-writer protocol, not proof against privileged SQL bypass. Validate every relevant writer and phantom case independently. Build the existing schedule health snapshot directly from those values without HealthAssessment.create, writes, audit, source mutation, network calls or policy administration. Invoke the new as-of-only schedule advice entrypoint with the strict ScheduleHealthSnapshot built from that exact source and the server-derived recipient. The entrypoint itself calls buildScheduleHealthAssessment and accepts no arbitrary generic health signal array or approval input, so blocker, freshness, completeness and external-signal kinds cannot be injected or filtered away. The snapshot assessedAt must equal the exact request asOf. Approval availability is explicitly unavailable, never a real zero count. Every source fact, including CLEAR contributors and reported status, requires the same authorized project/canonical read. No hidden input may be dropped while claiming completeness. If required inputs cannot be obtained or exceed bounds, fail closed as unavailable instead of falling back to old assessments or truncating.

## Point-in-time contract

The existing advice queue requires a future validUntil. Retention is not freshness and the existing wall-time resolver does not prove the first local-date transition for all supported zones. Add a separate, explicit schedule-only point-in-time pure entrypoint with an output schema that has an as-of instant but no validUntil. It must share the existing deterministic recommendation categorization, urgency/ranking, fixed wording and deep-immutability behavior, and must not weaken or alter the existing queue API or its expiry behavior. Refactor common pure internals only if the existing queue schema, public types, expiry validation and filtering, scoped filtering, ranking, wording and immutable output remain exact and all regressions pass. The new input accepts only a server-derived recipient and strict single-project ScheduleHealthSnapshot, and requires its project identity to match the authorized route; the snapshot assessedAt must exactly equal request asOf. buildScheduleHealthAssessment constructs its own schedule-only health result; arbitrary generic signals, pending approvals and external source records are not inputs. It exposes no approval input and has no generic claim of completeness outside schedule coverage.

Every request reauthenticates, reauthorizes and computes from the current transaction-owned snapshot. The response is non-cacheable and labeled “Schedule suggestions evaluated at [time]. Data or access may change; refresh before relying on it.” It is an observation, not a future authorization/freshness promise. Browser state must clear on session/project change, denial and visibility return; ignore late responses and show no stale fallback. Each evidence or project read separately reauthorizes. Previously disclosed data cannot be remotely erased; periodic refresh cannot promise instantaneous revocation. If the proposed pure entrypoint cannot preserve existing semantics without invented validity or a complete current snapshot, withhold the feature.

## Contract and tests

An empty available result means only that the schedule-only evaluation produced no eligible suggestions. A missing/unavailable assessment must not be presented as empty.
