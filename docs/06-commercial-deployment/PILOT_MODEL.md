# Pilot Model

## Purpose

Validate measurable customer value and implementation repeatability before expanding product scope.

## Recommended pilot

- Duration: 6 to 10 weeks after access
- One business unit or portfolio
- One Jira site
- One spreadsheet format
- Up to 20 active projects
- One PMO owner
- Three to five project managers
- Selected leadership users
- One update cadence
- One report template
- Shadow mode first
- Limited approved write-back after validation

## Pilot phases

### 1. Discovery and baseline

- Current process
- Reporting calendar
- Roles
- Source systems
- Field mapping
- Source authority
- Manual effort
- Security constraints
- Success measures

### 2. Configuration and shadow mode

- Connect read-only sources
- Import projects
- Configure freshness
- Run monitoring
- Compare signals with PM judgement
- Tune questions and rules

### 3. Controlled engagement

- Send selected update requests
- Measure response
- Enable PM escalation
- Confirm extracted responses

### 4. Controlled write-back

- Enable Jira comments or approved fields
- Review approval diff
- Validate receipts
- Monitor failure and correction

### 5. Leadership and reporting

- Pilot Q&A
- Dashboard
- Weekly digest
- Steering snapshot

### 6. Outcome review

- Compare with baseline
- Review adoption
- Identify configuration versus product gaps
- Decide production licence

## Pilot exit criteria

- At least one complete closed-loop workflow works with customer data.
- No critical access or write-control issue.
- PMs accept the update interaction.
- Leadership finds the evidence-backed answer useful.
- At least one agreed value metric improves.
- Remaining gaps are commercially and technically manageable.

## Pilot deliverables

- Configured deployment
- Source mapping
- Authority matrix
- Cadence and escalation policy
- Dashboard
- Report template
- Pilot metrics
- Security and operations handover
- Production proposal
