# Glossary

| Term | Meaning |
|---|---|
| Action receipt | Immutable record of a material action, including who requested it, who approved it, what changed, where it changed, supporting evidence and outcome. |
| Agent inference | A conclusion generated by AI from available evidence but not directly recorded or confirmed as fact. |
| Approval diff | Comparison of the current source value and the proposed new value before a material write. |
| Baseline | Approved project scope, schedule, cost or requirement reference against which change is measured. |
| BYOK | Bring Your Own Key. The customer supplies an AI provider credential or private model endpoint. |
| Canonical Project Model | Tool-neutral representation of portfolios, projects, milestones, work items, risks, dependencies, updates and evidence. |
| Cadence | Configured schedule for update requests, reminders, reports or reviews. |
| Connector | Isolated integration module for an external system such as Jira, Microsoft Graph or a spreadsheet source. |
| Contradiction | A material disagreement between sources or between a reported status and objective delivery signals. |
| Delivery assurance | Continuous verification that project information, commitments, risks and governance actions reflect delivery reality. |
| Evidence | Source record, document, communication or human confirmation supporting a project fact or claim. |
| Evidence ledger | Versioned store of project facts, sources, classifications, timestamps, confidence and approval state. |
| Fact classification | One of `SYSTEM_VERIFIED`, `HUMAN_CONFIRMED`, `AGENT_INFERENCE`, `CONFLICTING`, `STALE` or `UNKNOWN`. |
| Freshness | Whether information was verified within the configured valid time window. |
| Human in the loop | Required human review, confirmation or approval before selected actions or conclusions are treated as authoritative. |
| Material write | External change that may affect delivery commitment, status, ownership, baseline, customer communication or governance record. |
| PMO | Project Management Office or equivalent portfolio and delivery governance function. |
| RAID | Risks, Assumptions, Issues and Dependencies. |
| RAG | Red, Amber and Green project health classification. |
| Shadow mode | The product observes, analyzes and drafts actions without sending messages or writing to external systems. |
| Source authority | Approved rule defining which source governs a specific field or fact type. |
| Source of truth | Authoritative record for a defined data element. Different fields may have different authoritative sources. |
| Stale | Information older than its configured freshness period. |
| Watermelon project | Informal term for a project reported green while underlying evidence indicates material delivery risk. |
| Write-back | Controlled update from the product to an external source system. |
