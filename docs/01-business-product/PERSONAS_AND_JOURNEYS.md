# Personas and Journeys

## Persona 1: Executive Sponsor or Leadership User

### Goals

- Understand whether commitments are at risk
- Know why a delay occurred
- See what action is being taken
- Identify decisions requiring leadership
- Avoid waiting for a manually prepared report

### Concerns

- Incomplete or overly optimistic information
- Too much operational detail
- Unsupported AI conclusions
- Exposure to projects outside their authority

### Core journey

```text
Ask question
-> receive concise answer
-> inspect evidence
-> see freshness and uncertainty
-> review decision required
-> open project detail if needed
```

## Persona 2: Head of PMO

### Goals

- Ensure updates arrive on time
- Maintain consistent portfolio reporting
- Detect projects requiring management attention
- Enforce governance without manual administration
- Produce steering packs

### Core journey

```text
Open portfolio action queue
-> review missing updates and conflicts
-> approve escalations
-> review portfolio narrative
-> approve snapshot
-> distribute or publish
```

## Persona 3: Project Manager

### Goals

- Spend less time chasing and formatting
- See the most important delivery concerns
- Keep Jira and portfolio status aligned
- Control material commitments and communications
- Explain project status quickly

### Core journey

```text
Receive morning briefing
-> review recommended follow-ups
-> approve or edit update request
-> review returned owner response
-> approve structured write-back
-> see refreshed project status
```

## Persona 4: Scrum Master

### Goals

- Identify blockers, carryover and sprint risk
- Follow up with the right person
- Keep stand-up and Jira information aligned
- Escalate impediments at the right time

### Core journey

```text
Open sprint action queue
-> inspect stale blockers
-> send contextual request
-> review owner response
-> recommend or trigger PM escalation
```

## Persona 5: Team Lead

### Goals

- Resolve technical dependencies
- Identify unowned work and missing decisions
- Understand delivery impact
- Coordinate responsible developers without broad reminders

### Core journey

```text
Review team-level delivery concerns
-> inspect dependency evidence
-> assign or confirm an owner
-> provide forecast
-> notify PM of impact
```

## Persona 6: Contributor or Responsible Owner

### Goals

- Respond quickly
- Understand exactly what information is missing
- Avoid logging into several systems
- Correct the agent if it misunderstood

### Core journey

```text
Receive focused request
-> choose a quick response or write free text
-> review extracted interpretation
-> confirm or correct
-> see that the update was submitted
```

## Persona 7: PMO or System Administrator

### Goals

- Configure sources, mappings, roles, cadences and policies
- Keep credentials secure
- Monitor connector health
- Control AI routing and data use
- Upgrade the deployment safely

### Core journey

```text
Connect source
-> test access
-> map fields
-> configure authority and cadence
-> run shadow mode
-> review results
-> activate selected actions
```

## Cross-persona experience rule

The same verified facts must power all role views. The system may change detail, wording and recommended action by role, but it must not create conflicting versions of delivery truth.
